这是一份非常经典的计算机系统实验（CS:APP Attack Lab）。这个实验不仅有趣，而且能让你深刻理解**栈帧结构**、**缓冲区溢出**、**机器指令编码**以及**程序运行时的内存布局**。

由于每个学生的 `targetk` 程序是独一无二的（缓冲区大小、Cookie 值、地址随机化等都不同）1111，我无法给你直接的“答案”。但我可以教你一套**通用的破解方法论**，通过这些步骤，你可以找到属于你自己的答案。





### 0. 准备工作：知己知彼



在开始攻击之前，我们需要准备好工具和数据。

1. **解压与获取 Cookie**：

	- 运行 `tar -xvf targetk.tar` 解压。

	- 查看你的 Cookie：`cat cookie.txt` 2。记下这个 8 位十六进制数（例如 `0x1a7dd803`），后面会用到。

		

		

2. **反汇编代码**：

	- 这是最重要的步骤。你需要查看程序的汇编代码来寻找函数地址和栈的大小。

	- 运行：`objdump -d ctarget > ctarget.asm`

	- 运行：`objdump -d rtarget > rtarget.asm`

	- 这样你就得到了两个文本文件，里面包含了所有可执行代码的汇编指令 3。

### 第一部分：代码注入攻击 (CTARGET)



针对 `ctarget` 程序，内存栈是固定的且可执行 4。





#### Level 1: 重定向控制 (Touch1)





**目标**：利用 `getbuf` 的缓冲区溢出，覆盖返回地址，使其跳转到 `touch1` 函数 5。



**操作步骤**：

1. **寻找 `getbuf` 的缓冲区大小**：

	- 打开 `ctarget.asm`，搜索 `<getbuf>:`。
	- 查看第一条或第二条指令，通常是 `sub $0x??, %rsp`。
	- 这个 `0x??` 就是分配给缓冲区的空间大小。假设是 `0x28`（十进制 40）。

2. **寻找 `touch1` 的地址**：

	- 在 `ctarget.asm` 中搜索 `<touch1>:`。
	- 记下起始地址，例如 `0x4017c0`。

3. **构造攻击字符串**：

	- 你的输入需要填满缓冲区，然后紧接着覆盖返回地址。

	- **Padding（填充）**：填充字节数 = `getbuf` 分配的栈大小（例如 40 个字节的任意数据，如 `00`）。

	- **Address（地址）**：紧跟在填充后面，填入 `touch1` 的地址。

	- 

		**注意小端序 (Little Endian)**：如果地址是 `0x004017c0`，你在文件里要写成 `c0 17 40 00 00 00 00 00`（64位地址占8字节）6666。

		

		

4. **生成与测试**：

	- 创建一个文本文件 `exploit1.txt`，内容类似：

		Plaintext

		```
		00 00 ... (重复填充次数) ... 00
		c0 17 40 00 00 00 00 00
		```

	- 转换并运行：`./hex2raw < exploit1.txt | ./ctarget` 7。

		

		



#### Level 2: 注入代码 (Touch2)





**目标**：跳转到 `touch2`，并让 `touch2` 认为你传入了你的 Cookie 作为参数 8。



**核心知识**：

- x86-64 中，第一个参数放在 `%rdi` 寄存器中 9。

	

	

- 你需要注入一段代码将 Cookie 放入 `%rdi`，然后跳转到 `touch2`。

**操作步骤**：

1. **寻找注入位置（栈地址）**：

	- 我们需要知道 `getbuf` 的缓冲区在内存中的绝对地址，以便让程序跳转回去执行我们注入的代码。

	- 使用 GDB 调试：

		Bash

		```
		gdb ctarget
		(gdb) b getbuf
		(gdb) run
		(gdb) print /x $rsp
		```

	- 此时 `$rsp` 的值通常就是缓冲区的起始地址（因为 `sub` 指令刚执行完）。记下这个地址，例如 `0x5561dc78`。

2. **编写注入代码 (汇编)**：

	- 你需要做两件事：把 Cookie 放入 `%rdi`，然后去执行 `touch2`。

	- 文档建议不要直接用 `jmp`，而是用 `ret` 10。这就意味着你要把 `touch2` 的地址压入栈，然后执行 `ret`。

		

		

	- 汇编代码 `inject.s`:

		代码段

		```
		movq $0x1a7dd803, %rdi   /* 将你的 Cookie 移入 rdi */
		pushq $0x4017ec          /* 将 touch2 的地址压栈 (替换为实际地址) */
		retq                     /* 返回，这会弹出栈顶的 touch2 地址并跳转 */
		```

3. **编译机器码**：

	- 使用 `gcc -c inject.s` 然后 `objdump -d inject.o` 查看机器码 11。

		

		

	- 假设得到的字节序列是 `48 c7 c7 03 d8 7d 1a 68 ec 17 40 00 c3`。

4. **构造攻击字符串**：

	- **Payload**：上面生成的机器码。
	- **Padding**：填充剩下的缓冲区空间。长度 = 缓冲区总大小 - 机器码长度。
	- **Return Address**：覆盖 `getbuf` 的返回地址，将其指向**你注入代码的起始地址**（即步骤 1 中找到的栈地址）。

5. **组合**：`[机器码] + [填充] + [栈地址(小端序)]`。



#### Level 3: 字符串参数 (Touch3)





**目标**：跳转到 `touch3`，并传入一个指向“Cookie字符串形式”的指针 12。



**难点**：

- `%rdi` 必须存放一个**内存地址**，该地址指向一个字符串（例如 "1a7dd803"）。

- 你需要把这个字符串也放在栈里，并算出它的地址。

- 

	`touch3` 会调用 `hexmatch`，这会往栈里压入数据，如果你的字符串放得离栈顶太近，可能会被覆盖 13。

	

	

**操作步骤**：

1. **确定字符串放哪里**：

	- 最安全的地方是直接放在返回地址**之后**。这样它就在 `getbuf` 的栈帧之外，不会被 `hexmatch` 破坏。

2. **计算地址**：

	- 栈顶地址（Buffer Start） = A (通过 GDB 获得)。
	- 返回地址的位置 = A + 缓冲区大小。
	- 字符串的位置 = A + 缓冲区大小 + 8 (返回地址占8字节)。

3. **编写注入代码**：

	代码段

	```
	movq $0x5561dca8, %rdi  /* 将计算出的字符串地址移入 rdi */
	pushq $0x4018fa         /* touch3 的地址 */
	retq
	```

4. **构造攻击字符串**：

	- `[注入代码机器码]`

	- `[填充 (直到填满缓冲区)]`

	- `[栈地址 (指向你的注入代码)]`  <-- 覆盖原返回地址

	- 

		`[Cookie 的十六进制字符串编码]` <-- 字符串本身，例如 `31 61 37...` (ASCII码)，记得结尾加 `00` 14。

### 第二部分：返回导向编程 (ROP) - RTARGET



针对 `rtarget`，栈不可执行且地址随机化 15。我们不能注入代码，只能利用现有的代码片段（Gadgets）。





#### Level 4: ROP 调用 Touch2





**目标**：利用 Gadget Farm 中的指令片段，将 Cookie 放入 `%rdi`，然后调用 `touch2` 16。



原理：

我们需要在栈上构造一串地址。当执行 ret 时，CPU 会弹出栈顶地址并跳转。如果该地址指向 popq %rdi; ret，CPU 就会执行它，从栈中再弹出一个值放入 %rdi，然后再次 ret 跳转到下一个 Gadget。

**所需 Gadget**：

1. `popq %rdi; ret`：用于从栈中把 Cookie 弹入 `%rdi`。
2. `touch2` 的地址。

**操作步骤**：

1. **在 `rtarget.asm` 中寻找 Gadget**：

	- 搜索 `start_farm` 和 `end_farm` 之间的代码 17。

		

		

	- 寻找编码为 `5f c3` 的字节序列（`pop %rdi; ret`）。

	- 如果找不到直接的，可能需要找 `pop %rax; ret` (58 c3) 和 `mov %rax, %rdi; ret` (48 89 c7 c3) 的组合 18。

		

		

	- *提示*：指令可能隐藏在其他指令的字节码中。例如 `movl $0xc78948d4, (%rdi)` 的机器码是 `c7 07 d4 48 89 c7`。如果你从第 3 个字节开始看，就是 `48 89 c7` (`mov %rax, %rdi`)。加上后面的 `c3` (`ret`)，这就是一个 Gadget。

2. **构造栈结构**：

	- `[填充 (填满缓冲区)]`
	- `[Gadget1 地址 (pop rdi)]`
	- `[Cookie 值]` (这是给 pop rdi 吃的)
	- `[Touch2 地址]`



#### Level 5: ROP 调用 Touch3 (高难度)



**目标**：调用 `touch3`，传入指向 Cookie 字符串的指针。

**难点**：

- 栈地址是随机的，你不能像 Level 3 那样硬编码字符串地址。
- 你需要获得当前的栈指针 `%rsp`，计算出字符串在栈中的相对位置，然后把这个地址传给 `%rdi`。
- 这需要利用 `mov %rsp, %rax` 或者类似的 Gadget 进行算术运算。

**思路**：

1. 你需要找到能把 `%rsp` 的值复制到其他寄存器（如 `%rax` 或 `%rdi`）的 Gadget。

2. 利用 `add` 指令调整这个地址（加上偏移量，使其指向你放置字符串的位置）。

3. 最后将计算好的地址放入 `%rdi` 并调用 `touch3`。

4. 这是一个“额外加分”题，通常需要组合 8 个左右的 Gadget 19。

### 重要提示与技巧



- **GDB 是好朋友**：

	- 使用 `disas getbuf` 查看汇编。
	- 使用 `stepi` (si) 单步执行汇编指令。
	- 使用 `x/20gx $rsp` 查看栈顶的内存数据。

- **小端序陷阱**：如果不确定，先写下十六进制，然后两两一组反过来写。

	- `0x4017c0` -> `c0 17 40 00 00 00 00 00`。

- **Hex2Raw**：

	- 记得使用 `hex2raw` 处理你的输入，因为它能帮你转换十六进制字符到原始字节，并且处理掉不小心输入的换行符问题。exploit 字符串中不能包含 `0x0a` (`\n`) 20。
