### 第一部分：数据的存储与表示 (Data Storage)

#### 1. 字长与寻址 (Word Size & Addressing)

- **概念**：计算机的“字长”（Word Size）决定了虚拟地址空间的大小 。
	- **32位机器**：字长4字节，指针也是4字节。
	- ==**64位机器**（现在的主流，也是考试默认环境）：字长8字节，指针是8字节 。==
- **考试坑点**：
	- 看到 `char *p;`，问你 `sizeof(p)` 是多少？
	- **答案**：在64位系统下是 **8**，而不是1（char的大小）！指针的大小只跟机器字长有关，跟它指向什么类型无关。

#### 2. 大端法 vs 小端法 (Big Endian vs Little Endian) —— **⭐必考五星级考点**

这是期末考**填空题**或**内存分析题**的常客。

- **定义**：对于一个跨越多字节的数据（比如 `int x` 占4字节），它在内存里怎么摆？
	- **大端法 (Big Endian)**：高位字节（MSB）放在低地址 。符合人类阅读习惯。
	- **小端法 (Little Endian)**：低位字节（LSB）放在低地址 。**Intel x86-64（你的实验环境）是小端的**。
- **😼 猫咪例子辅助记忆**： 假设 `txrcat` 的编号是十六进制数 `0x12345678`。
	- **大端猫**（头朝前）：头（高位 `12`）先进门（低地址）。内存里是：`12 34 56 78`。
	- **小端猫**（尾巴朝前）：尾巴（低位 `78`）先进门（低地址）。内存里是：`78 56 34 12`。
- **📝 考试怎么考？** (参考 Slide 12 ) 题目：`int x = 0x12345678;` 存放在地址 `0x100` 处。请写出内存 `0x100` ~ `0x103` 的值（x86-64环境）。
	- **解题思路**：
		1. x86-64 = **小端法**。
		2. 取出最低位字节：`78`。
		3. 放在最低地址 `0x100`。
	- **答案**：
		- `0x100`: `78`
		- `0x101`: `56`
		- `0x102`: `34`
		- `0x103`: `12`

#### 3. 内存对齐 (Alignment) —— **⭐常考点**

为了提高CPU访问内存的效率，数据不是随便塞在内存里的，要有“规矩” 。

- **规则**：

	- `int` (4字节) 的地址必须是 4 的倍数。
	- `double` (8字节) 的地址必须是 8 的倍数。
	- `char` (1字节) 随便放。

- **后果**：如果不满足，中间就要填充“垃圾数据”（Padding），这会导致结构体大小变大 。

- **例子** (参考 Slide 16 )：

	C

	```
	struct S1 {
	    int i;   // 4字节
	    char c;  // 1字节
	    int j;   // 4字节
	};
	```

	- **内存布局**：
		- `i`: 占 0,1,2,3
		- `c`: 占 4
		- `j`: **不能**从 5 开始，因为 5 不是 4 的倍数！必须跳过 5,6,7，从 **8** 开始。
		- **总大小**：12字节。
	- **优化**：如果把 `char c` 放到最后，或者把两个 `int` 放在一起，可能只需要 8 字节或者更紧凑。
	- **考试Tip**：计算 `sizeof(struct)` 时，一定要画格子，数清楚哪里补了空位。

### 第二部分：位操作 (Bit-Level Operations)

#### 1. 逻辑运算 vs 位运算 (Logic vs Bitwise) —— **💥 易错重灾区**

这是C语言最容易混淆的地方，也是“陷阱题”的来源。

- **位运算** (`&`, `|`, `~`, `^`) ：
	- 对**每一位**分别操作。
	- 例：`0x69 & 0x55` -> `0110 1001 & 0101 0101` = `0100 0001` (`0x41`) 。
- **逻辑运算** (`&&`, `||`, `!`) ：
	- 只认 **0 (False)** 和 **非0 (True)**。
	- **短路特性**：如果第一个操作数能决定结果，第二个就不执行（位运算没有这个特性！）。
	- 例：`0x69 && 0x55` -> `True && True` -> `1` (`0x01`) 。
- **考试坑点**：
	- `!0x41` 是多少？ -> `0x00`。
	- `!!0x41` 是多少？ -> `0x01`。
	- `~0x41` 是多少？ -> `0xBE` (按位取反)。
	- ==**记住**：逻辑运算的结果只能是 `0x00` 或 `0x01`，位运算结果可以是任何数。==

#### 2. 移位操作 (Shift Operations) —— **⭐ 必考应用题**

移位分为**左移**和**右移**。左移很简单，右移有玄机 。

- **左移 (`<<`)**：
	- 丢弃高位，低位**补 0**。
- **右移 (`>>`)**：
	- **逻辑右移 (Logical)**：一般用于无符号数 (`unsigned`)。左边**补 0** 。
	- **算术右移 (Arithmetic)**：一般用于有符号数 (`int`)。左边**补符号位**（即：原来最高位是1就补1，是0就补0） 。这是为了保持负数的性质。
- **😼 猫咪例子**： 假设 `x` 是一个8位的有符号数：`1010 0010` (这其实是个负数)。
	- `x >> 2` (算术右移)：因为最高位是 **1** (猫耳朵是黑的)，所以右移后左边补 **1** (补黑耳朵)。
		- 结果：`1110 1000`。
	- 如果是 `unsigned x`，同样是 `1010 0010`。
	- `x >> 2` (逻辑右移)：无视符号，直接补 **0**。
		- 结果：`0010 1000`。
- **考试Tip**： 如果题目给你一个 `int` (有符号)，问你 `x >> k` 的结果，一定要检查 x 的最高位是不是 1。如果是 1，记得补 1，不要补 0！

### 第三部分：整数表示 (Integer Representation)

#### 1. 有符号数的表示：补码 (Two's Complement) —— **⭐核心原理**

计算机怎么表示负数？它不画负号，而是用**最高位（MSB）**的权重为负来表示 。

- **公式**：对于一个 $w$ 位的整数，最高位的权重是 $-2^{w-1}$，其余位权重是正的 $2^i$。
- **例子**（以4位二进制为例）：
	- **无符号** `1010` = $1 \times 2^3 + 0 + 1 \times 2^1 + 0 = 8 + 2 = 10$。
	- **补码** `1010` = **$-1 \times 2^3$** + $0 + 1 \times 2^1 + 0 = -8 + 2 = -6$。
- **重要范围** ：
	- **TMin（最小负数）**：`100...0`。最高位是1，后面全0。值为 $-2^{w-1}$。
	- **TMax（最大正数）**：`011...1`。最高位是0，后面全1。值为 $2^{w-1} - 1$。
	- **不对称性**：`|TMin| = TMax + 1`。也就是说，负数能表示的范围比正数多一个（因为0占用了正数的一半边）。这也是为什么 `abs(TMin)` 会溢出！

#### 2. 有符号 vs 无符号转换 (Casting) —— **💥必考坑点**

这是C语言最容易让你掉坑的地方，也是**期末代码题的高频考点**。

- **黄金法则**：**位模式不变，解释方式改变** 。
	- 当你把一个 `int` 强制转为 `unsigned`，或者反过来，它在内存里的二进制位**完全不动**，只是你戴的眼镜变了。
- **经典案例** ：
	- `int x = -1;`
	- 二进制（32位）：`1111 ... 1111` (全1)。
	- 转成 `unsigned u = (unsigned)x;`
	- 二进制还是全1。但是无符号的“全1”是超级大的正数（**UMax**，即 $2^{32}-1$）。
	- **结论**：**-1 转换成无符号数，会变成最大的正整数！**

#### 3. 隐式转换陷阱 (Implicit Casting) —— **⚡️高危预警**

如果在同一个表达式里，既有 `int` 又有 `unsigned`，C语言会**悄悄地**把有符号数转成无符号数 。

- 小测试题（期末真题风格）：

	判断真假：-1 < 0U

	- **分析**：
		1. 左边 `-1` 是 `int`。
		2. 右边 `0U` 是 `unsigned`。
		3. 触发隐式转换！`-1` 变成 `unsigned`。
		4. `-1` 变成 `unsigned` 后是 `UMax`（最大正整数）。
		5. 比较变成：`UMax < 0`？
	- **结果**：**False**（假）。
	- **后果**：这在 `for` 循环或者 `if` 判断里是致命的 Bug。

#### 4. 扩展与截断 (Sign Extension & Truncation)

- **符号扩展**（小变大，比如 `short` -> `int`）：
	- **无符号数**：前面补 **0**（Zero Extension）。
	- **有符号数**：前面补 **符号位**（Sign Extension）。
	- **例子**：`short x = -10` (二进制 `1111 0110`)。
		- 转成 `int`：前面疯狂补1 -> `1111 1111 1111 0110`。值保持 `-10` 不变。
- **截断**（大变小，比如 `int` -> `short`）：
	- 直接**咔嚓**切掉高位。
	- **后果**：数值可能会剧烈变化，甚至符号反转。
	- **例子**：`int i = 32768` (二进制 `0000 ... 1000 0000 0000 0000`)。
		- 截断成 `short`（16位）：剩下后16位 `1000 0000 0000 0000`。
		- 这在 `short` 里是 **-32768**（TMin）。
		- 正数变负数了！

### 总结一下这三个坑（记在小本本上）：

1. **比较大小时**：只要一边是 `unsigned`，另一边的 `int` 就会立刻叛变变成 `unsigned`（负数变大正数）。
2. **小变大时**：看原类型。原类型是**有符号** (`char`, `short`, `int`)，就补**符号位**（1补1，0补0）；原类型是**无符号** (`unsigned ...`)，才补 **0**。

### 第一部分：整数加法与溢出 (Integer Addition & Overflow)

#### 1. 机器的“无知” (Identical Bit-Level Behavior)

这是 CSAPP 最核心的哲学之一：**CPU 其实很笨，它根本分不清你给它的是有符号数（int）还是无符号数（unsigned）。**

- **原理**：无论是有符号还是无符号，CPU 加法器都用**完全相同**的电路、完全相同的位操作规则进行相加。
- **区别**：在于**我们怎么解释结果**，以及 CPU 生成的**标志位（Flags）**不同。

#### 2. 溢出判断 (Overflow Detection) —— **⭐ 必考判断题**

考试经常给你两个数，问你加法后标志位（CF, ZF, SF, OF）各是多少。

| **标志位** | **全称** | **关注对象** | **什么时候置 1 (True)** | **经典例子 (假设 8-bit)**    |
| ---------- | -------- | ------------ | ----------------------- | ---------------------------- |
| **ZF**     | Zero     | 所有人       | 结果 == 0               | `5 - 5`                      |
| **SF**     | Sign     | 有符号数     | 结果最高位 == 1         | `0 - 1` (结果 `0xFF`，SF=1)  |
| **CF**     | Carry    | **无符号数** | 最高位进位/借位         | `0xFF + 1` (结果0，但进位了) |
| **OF**     | Overflow | **有符号数** | 正+正=负 或 负+负=正    | `0x7F + 1` (127+1=-128)      |

- **无符号溢出 (Unsigned Overflow)**：
	- 看 **进位标志 (CF, Carry Flag)**。
	- 如果最高位向更高位进位了（比如两个很大的正数相加，超过了位数限制），CF = 1。
	- **判定公式**：如果 `s = u + v`，且 `s < u`（结果反而变小了），说明发生了无符号溢出。
- **有符号溢出 (Signed/Two's Complement Overflow)**：
	- 看 **溢出标志 (OF, Overflow Flag)** 。
	- **口诀**：**“正正得负，负负得正”** 就是溢出。
		- 两个正数相加，结果变成负数 $\rightarrow$ **正溢出 (PosOver)**。
		- 两个负数相加，结果变成正数 $\rightarrow$ **负溢出 (NegOver)**。
		- *注意：一正一负相加永远不会溢出！*

### 第二部分：取反与求补 (Negation)

#### 1. 补码取反公式 —— **⭐ 基础公式**

想要得到 -x，公式永远是：$$-x = \sim x + 1$$

也就是：**按位取反，末位加一** 。

#### 2. 两个特例 (Corner Cases) —— **💥 选择题陷阱**

有两个特殊的数，取反后**还是它自己**：

1. **0**：`~0 + 1` = `0xFF...F + 1` = `0` (溢出截断)。

2. **TMin (最小负数)**：比如 8 位的 `-128` (`1000 0000`)。

	- 取反 `~` $\rightarrow$ `0111 1111` (`127`)

	- 加 1 $\rightarrow$ `1000 0000` (`-128`)

	- **结论**：`TMin` 的相反数还是 `TMin`！这在编程中会导致 `abs(TMin)` 依然是负数 。

### 第三部分：乘除法的“移位魔法” (Shift Operations)

这一块是代码优化题和填空题的**绝对重灾区**。因为乘除法指令很慢，编译器喜欢用移位来优化。

#### 1. 乘法优化 (Multiplication by Constant)

- **原理**：将乘数拆成 2 的幂次之和。
- **例子** ：计算 `x * 20`。
	- $20 = 16 + 4 = 2^4 + 2^2$
	- C代码优化为：`(x << 4) + (x << 2)`
	- 只用了 2 次移位和 1 次加法，比乘法指令快得多。

#### 2. 除法优化 (Division by Power of 2) —— **🔥🔥 超级重难点**

除法分两种情况，**负数的除法**是全书最难懂的细节之一。

- **无符号数 / 正数 (Unsigned / Positive)**：

	- 直接 **逻辑/算术右移**。
	- `x / 8` $\rightarrow$ `x >> 3`。
	- 效果：**向下舍入 (Round Down)**。

- **负数 (Negative)**：

	- 如果我们直接对负数进行算术右移（补符号位），结果是**向下舍入**（往 $-\infty$ 方向）。

	- **但是！** C 语言规定，整数除法必须**向 0 舍入**（Round Toward Zero）。

	- *例子*：`-3 / 2` 应该等于 `-1`（向0舍入）。

		- `-3` 二进制（4位）: `1101`。
		- 直接右移 `1101 >> 1` $\rightarrow$ `1110` (即 -2)。
		- **结果不对！** 变成了 -2（向下舍入）。

	- **解决方案 (Biasing)**：**“偏置值”技巧** 。

		- 在右移之前，先给这个负数“加点料”（Bias）。

		- **Bias 值**：$(1 \ll k) - 1$ （也就是 $2^k - 1$）（这里的 $k$ 其实就是**除数中 2 的幂次**，或者更直白地说，就是**你要右移的位数**。）。

		- 最终公式：

			$$(x < 0) ? (x + (1 \ll k) - 1) \gg k : x \gg k$$

	- *验证例子*：`-3 / 2` ($k=1$，Bias = $2^1-1 = 1$)。

		- $(-3 + 1) \gg 1$
		- $-2 \gg 1$
		- $ 1110 \gg 1 $  $\rightarrow$ `1111` (即 -1)。
		- **对了！**

### 第四部分：C 语言陷阱题 (C Puzzles)

Slide 36 列出了一堆判断题，这些是**期末必考**的逻辑题。我们挑几个最容易错的分析 ：

1. **`x < 0` $\Rightarrow$ `(x \* 2) < 0` ?**
	- **False**。
	- **原因**：溢出！如果 `x` 是 TMin，`x * 2` 会变成 0。如果 `x` 很大负数，乘 2 可能溢出变成正数。
2. **`ux >= 0` ?**
	- **True**。
	- **原因**：`ux` 是 `unsigned`，无符号数永远 $\ge 0$。
3. **`x > y` $\Rightarrow$ `-x < -y` ?**
	- **False**。
	- **原因**：**TMin**！如果 `y` 是 TMin，`-y` 还是 TMin（负数）。比如 `0 > -2147483648`，但 `-0 (0) < -(-2147483648) (-2147483648)` 是假的。
4. **`(x | -x) >> 31 == -1` ?** (假设 x != 0)
	- **True**。
	- **原因**：只要 `x != 0`，`x` 和 `-x` 中必有一个的符号位是 1。
	- `x | -x` 的符号位一定是 1。
	- 算术右移 31 位（符号扩展），结果就是全 1，即 `-1`。

## 04-float

### 第一部分：IEEE 754 核心公式 (The Formula)

计算机里的浮点数，其实就是科学计数法的二进制版。

公式如下（死记！）：

$$V = (-1)^s \times M \times 2^E$$

这个公式把 32 位（单精度 float）或 64 位（双精度 double）切成了三块：

1. **符号位 s (Sign)**：决定正负。1 是负，0 是正。
2. **阶码 exp (Exponent)**：决定大小范围（相当于科学计数法里的 $10^n$ 的 $n$）。
	- *注意：这里存的是一个无符号整数，实际使用时要减去偏置值 (Bias)。*
3. **尾数 frac (Significand/Mantissa)**：决定精度（相当于 $1.23 \times 10^n$ 里的 $1.23$）。

**位数分布（必考）：**

- **float (32位)**：s=1, **exp=8**, frac=23。
- **double (64位)**：s=1, **exp=11**, frac=52。

------

### 第二部分：三种形态 (The Three Cases) —— **⭐ 考试绝对核心**

系统根据 **阶码 (exp)** 的不同，把浮点数分为三类。这也是考试最喜欢让你判断的地方。

#### 1. 规格化数 (Normalized) —— 最常见的形态

- **特征**：`exp` 的位模式**不全为 0** 且 **不全为 1**。
- **阶码 E**：$E = exp - Bias$。
	- **Bias (偏置值)**：$2^{k-1} - 1$。
	- *单精度 Bias = 127*，*双精度 Bias = 1023*。
- **尾数 M**：**$1.frac$**。
	- *关键点*：因为是二进制，规格化数的首位肯定是 1（就像科学计数法首位不能是 0），所以计算机**省掉了这个 1**（隐含的 1），只存小数点后面的部分，白嫖了一位精度！

### 例子 ：将 5.75 转换为 32 位浮点数

**第一步：转换为二进制**

- **整数部分**：$5$ $\rightarrow$ `101`
- **小数部分**：$0.75$
	- $0.75 \times 2 = 1.5$ $\rightarrow$ 取整数 **1**，剩 $0.5$
	- $0.5 \times 2 = 1.0$ $\rightarrow$ 取整数 **1**，剩 $0$（结束）
	- 所以小数部分是 `.11`
- **合并**：$5.75 = 101.11_{(2)}$

**第二步：规格化（移动小数点）**

- 我们要把它变成 $1.xxxx \times 2^E$ 的形式。
- 小数点向左移 **2** 位：$1.0111 \times 2^2$。
- **提取关键信息**：
	- **符号 $s$**：正数，所以 **0**。
	- **真实指数 $E$**：**2**。
	- **尾数 $M$**：$1.0111$（去掉隐含的整数1，剩下 **0111**）。

**第三步：计算阶码 ($exp$) 和 填充尾数 ($frac$)**

- **阶码 ($exp$)**：
	- 公式：$exp = E + Bias$
	- 计算：$2 + 127 = 129$
	- 二进制：$129 = 128 + 1 = \mathbf{10000001}$
- **尾数 ($frac$)**：
	- 取第二步剩下的小数部分 `0111`。
	- 补足 23 位：`0111 0000 0000 0000 0000 000`

**第四步：拼装**

- **s (1位)** | **exp (8位)** | **frac (23位)**
- `0` | `10000001` | `01110000000000000000000`
- **十六进制表示**：`0x40B80000`

#### ==2. 非规格化数 (Denormalized) —— 接近 0 的数==

- **特征**：`exp` **全为 0** (`00...0`)。
- **阶码 E**：**$E = 1 - Bias$**。（**注意！不是 $0 - Bias$**，这是为了和规格化数平滑连接，考点！）
- **尾数 M**：**$0.frac$**。
	- *关键点*：首位隐含的是 0。
- **用途**：表示 **0**（+0.0 和 -0.0）以及**非常接近 0 的小数**。

#### 3. 特殊值 (Special) —— 无穷大和 NaN

- **特征**：`exp` **全为 1** (`11...1`)。
- **分两种**：
	1. **无穷大 (Infinity)**：`frac` 全为 0。表示溢出（比如 $1.0/0.0$）。
	2. **NaN (Not a Number)**：`frac` 不全为 0。表示非法运算（比如 $\sqrt{-1}$ 或 $\infty - \infty$）。

------

### 第三部分：舍入规则 (Rounding) —— **⭐ 易错点**

计算机小数点后面的位数有限，存不下时必须舍入。IEEE 754 默认使用 **向偶数舍入 (Round to Even)**，也叫“向最接近的值舍入”。

- **规则**：
	1. 如果不处于“正中间”，就四舍五入（离谁近去谁那）。
	2. 如果**恰好在正中间**（比如 1.5, 2.5），则**向最低有效位是偶数**的方向舍入。
- **例子**（假设我们要保留整数位）：
	- $1.4 \rightarrow 1$ (离 1 近)
	- $1.6 \rightarrow 2$ (离 2 近)
	- $1.5 \rightarrow 2$ (在中间，2 是偶数，1 是奇数，去 2)
	- $2.5 \rightarrow 2$ (在中间，2 是偶数，3 是奇数，去 2)
- **目的**：避免统计偏差（一半向上舍入，一半向下，统计平均值更准）。

------

### 第四部分：浮点运算的坑 (Floating Point Puzzles)

C 语言中 `int`, `float`, `double` 混用时的逻辑题。

1. **结合律失效**：

	- 浮点加法**不满足**结合律！
	- $(3.14 + 1e20) - 1e20 = 0.0$ （3.14 太小被大数吃掉了）
	- $3.14 + (1e20 - 1e20) = 3.14$

	例子

	- `x = 3.14`
	- `y = 1e20` (1 后面 20 个 0，超级巨大的数)
	- `z = -1e20` (超级巨大的负数)

	**左边算**：`(3.14 + 1e20) - 1e20`

	1. `3.14 + 1e20`：`3.14` 相对于 `1e20` 就像尘埃一样微小。由于对齐阶码，`3.14` 会被移位移没了。结果等于 `1e20`。
	2. `1e20 - 1e20`：结果是 **0.0**。

	**右边算**：`3.14 + (1e20 - 1e20)`

	1. `1e20 - 1e20`：结果是 **0.0**。
	2. `3.14 + 0.0`：结果是 **3.14**。

	**结论**：`0.0 != 3.14`。

2. **类型转换 (Casting)**：

	- `int` $\rightarrow$ `float`：可能**丢失精度**（int 32位有效数字，float 只有 23 位），但不会溢出。

	取一个比较大的奇数：`x = 16777217` (即 $2^{24} + 1$)。

	转为 `float`：由于 `float` 的尾数只有 23 位（加上隐含的 1 位，共 24 位精度），它存不下 $2^{24} + 1$ 这个数的最后一位 `1`。

	**结果**：它被迫舍入，变成了 $16777216.0$ ($2^{24}$)。

	转回 `int`：变成了 `16777216`。

	**结论**：`16777217 != 16777216`，原值变了！

	- `int` / `float` $\rightarrow$ `double`：完美转换，既不丢失精度也不溢出（double 有 52 位，够装）。
	- `double` $\rightarrow$ `float`：可能**溢出**（变成 $\infty$）也可能**舍入**。
	- `float` / `double` $\rightarrow$ `int`：**向 0 截断**（Truncation），像 `1.99` 会变成 `1`。

## 05-machine-basics

---

### 第一阶段：认识“战场”与“士兵”

在 C 语言里，你看到的是变量 `x`, `y`, `i`。但在汇编世界里，没有变量名，只有**地址**和**寄存器**。

#### 1. 我们的新名字：汇编后缀 (Data Sizes) —— **⭐ 基础中的基础**

在汇编代码中，你经常看到 `movq`, `addl`, `movb`。这些后缀 `q`, `l`, `b` 代表什么？它们代表**操作数据的大小**。

**一定要背下来的对应表**（参考 Slide 19）：

| **C 语言类型**   | **Intel 数据类型** | **汇编后缀** | **大小 (Bytes)** | **备注**    |
| ---------------- | ------------------ | ------------ | ---------------- | ----------- |
| `char`           | Byte               | **b**        | 1                | 字节        |
| `short`          | Word               | **w**        | 2                | 字          |
| `int`            | Double word        | **l**        | 4                | 双字 (Long) |
| `long`, `char *` | Quad word          | **q**        | 8                | 四字 (Quad) |

---

#### 2. 认识“士兵”：16 个通用寄存器 (Registers) —— **⭐ 核心背诵内容**

CPU 里有 16 个极其珍贵、速度极快的存储格，叫**寄存器**。所有运算（加减乘除）都必须在寄存器里进行，不能直接在内存里做。

你需要重点记住这几类“士兵”的职责（参考 Slide 15-18）：

1. **返回值专员**：
	- **`%rax`**：**函数返回值**。函数算完的结果通常都放在这里。
2. **参数专员** (函数传参的前6个参数，顺序固定，**必考！**)：
	- 第1个参数：**`%rdi`**
	- 第2个参数：**`%rsi`**
	- 第3个参数：**`%rdx`**
	- 第4个参数：**`%rcx`**
	- 第5个参数：**`%r8`**
	- 第6个参数：**`%r9`**
3. **特种兵**：
	- **`%rsp`** (Stack Pointer)：**栈指针**。永远指向当前栈顶。千万别乱改它！
4. **套娃结构**（32位兼容 64位）：
	- 寄存器是“套娃”的。
	- **`%rax`** 是完整的 **64位**（8字节）。
	- **`%eax`** 是 `%rax` 的**低32位**（4字节）。
	- 如果操作 `int` 类型（4字节），汇编指令会用 `%eax`；如果操作 `long` 或指针（8字节），会用 `%rax`。

---

#### 3. 认识“操作数”：三种形态 (Operands) —— **⭐ 读懂代码的关键**

汇编指令比如 `movq Source, Dest`，这里的 Source 和 Dest 长什么样？只有三种可能（参考 Slide 21）：

1. **立即数 (Immediate)**：就是常数。
	- **格式**：**`$`** 开头。
	- *例子*：`$0x100` (数 256), `$-1` (数 -1)。
2. **寄存器 (Register)**：寄存器里的值。
	- **格式**：**`%`** 开头。
	- *例子*：`%rax` (取 rax 寄存器里面的值，比如 temp = rax)。
3. **内存引用 (Memory)**：**最像 C 语言指针的地方**。
	- **格式**：**`(...)`** 包起来。
	- *例子*：`(%rax)`。
	- *含义*：**去访问 `%rax` 里存的那个地址**。
	- *类比 C 语言*：如果 `%rax` 是指针 `p`，那么 `(%rax)` 就是 **`\*p`** (解引用)。

---

### 第二阶段：破解“内存寻址”的密码

在汇编里，访问内存（指针解引用）的方式非常灵活，不仅仅是 `(%rax)` 这么简单。它有一个通用的“万能公式”。

#### 1. 万能寻址公式 (The Magic Formula) —— **⭐ 必考计算题**

汇编指令的操作数如果长这样：`D(Rb, Ri, S)`，它代表什么地址？

公式：

$$\text{Address} = \text{Reg}[Rb] + \text{Reg}[Ri] \times S + D$$

- **$Rb$ (Base)**：基址寄存器（起跑线）。
- **$Ri$ (Index)**：变址寄存器（跑几步）。
- **$S$ (Scale)**：比例因子（每步多大）。**注意：S 只能是 1, 2, 4, 8**（对应 char, short, int, long/ptr 的大小）。
- **$D$ (Displacement)**：偏移量（常数，最后微调的位置）。

😼 猫咪例子：

假设 yljcat 在操场跑步。

- **$Rb$ (基址)**：起跑线在 100米处。
- **$Ri$ (索引)**：她跑了 5 步。
- **$S$ (比例)**：她是只大猫，一步能跨 4 米 ($S=4$)。
- **$D$ (偏移)**：最后她又往前挪了 10 米 ($D=10$)。
- **最终位置**：$100 + 5 \times 4 + 10 = 130$ 米。

**对应汇编写做**：`10(%rax, %rcx, 4)`  (假设 `%rax`=100, `%rcx`=5)。

------

#### 2. 最强指令：`leaq` (Load Effective Address) —— **🔥🔥 超级重难点**

这是 CSAPP 里的“扫地僧”指令。它名字叫“加载有效地址”，但它经常**不干正事**。

- **正经用法**：计算一个指针的地址，但不去访问内存（不解引用）。
	- `leaq (%rax), %rdx` $\rightarrow$ `rdx = rax` (把 rax 的值赋给 rdx，没去访问内存)。
	- `leaq 4(%rax), %rdx` $\rightarrow$ `rdx = rax + 4` (指针后移 4 字节)。
- **不正经用法（必考）**：**把它当“加法器”和“乘法器”用！**
	- 因为那个万能公式 $Rb + Ri \times S + D$ 本质上就是一个算术运算。
	- 编译器发现 `leaq` 算加法和乘法（乘 1,2,4,8）特别快，就拿它来做数学题，跟内存地址一毛钱关系都没有。

**🌰 经典考题（逆向工程）**：

代码段

```
leaq (%rdi, %rdi, 2), %rax
```

- **分析**：
	- $Rb = \text{rdi}$
	- $Ri = \text{rdi}$
	- $S = 2$
	- $D = 0$
- **计算**：`rax = rdi + rdi * 2 = 3 * rdi`。
- **C 语言对应**：`return x * 3;`
- **感叹**：看，这明明是在算 $x \times 3$，却用了一个叫“取地址”的指令。这就是 `leaq` 的欺骗性！

------

#### 3. 算术指令 (Arithmetic Instructions) —— **⭐ 了解即可**

除了 `leaq`，其他的算术指令就很老实了：

- **二元操作**：`addq Src, Dest` $\rightarrow$ `Dest = Dest + Src`
	- 注意：结果存在第二个操作数里（覆盖原来的值）。
- **一元操作**：`incq Dest` $\rightarrow$ `Dest = Dest + 1` (自增)
	- `decq` (自减), `negq` (取负), `notq` (取反)。

---

### 第三阶段：栈与逻辑魔法

#### 1. 栈 (The Stack) —— **⭐ 必考数据结构**

在汇编里，栈是用来存临时数据和函数调用的核心区域。

- **栈的生长方向**：**向下生长**（从高地址往低地址长）。
	- *记忆法*：就像搭积木，但是是**从天花板往下搭**的倒立积木。
- **栈顶指针 `%rsp`**：永远指向栈的最下面一个元素（地址最小的那个）。

**两个核心指令 (Pop & Push)**：

1. **`pushq Src` (入栈)**：
	- **动作分解**：
		1. 先让栈顶指针**减 8** (`%rsp` 变小，腾出空间)。
		2. 把数据写入新的 `%rsp` 指向的内存。
	- **C语言描述**：`*(--rsp) = val;`
2. **`popq Dest` (出栈)**：
	- **动作分解**：
		1. 先读出 `%rsp` 指向的数据。
		2. 再让栈顶指针**加 8** (`%rsp` 变大，回收空间)。
	- **C语言描述**：`val = *(rsp++);`

**😼 思考题**： 如果我执行 `pushq %rax`，然后再 `popq %rax`，寄存器 `%rax` 的值变了吗？

- **答案**：没变。但是内存里的栈顶位置曾经存过它。

------

#### 2. 逻辑与移位指令 (Logic & Shift) —— **⭐ 常用工具**

除了加减乘，CPU 还经常做位操作。

- **常见逻辑指令**：
	- `andq`, `orq`, `xorq` (异或), `notq` (取反)。
	- **考点**：**`xorq %rax, %rax`** 是什么意思？
		- 自己异或自己，结果永远是 **0**。
		- 这是汇编里**把寄存器清零**的最快方法（比 `movq $0, %rax` 还快，字节数更少）。
- **移位指令 (Shift)**：
	- **左移**：`salq` 或 `shlq` (效果一样，低位补0)。
	- **右移**：
		- **`sarq`** (算术右移，**补符号位**，用于有符号数除法)。
		- **`shrq`** (逻辑右移，**补0**，用于无符号数)。
	- *这正好呼应了我们上一章讲的整数运算！*

## 06-machine-control

---

### 第一阶段：CPU 的红绿灯 (Condition Codes & Jumps)

我们之前学过四个标志位（CF, ZF, SF, OF），它们就是 CPU 的“情绪”。CPU 不会思考，它只会看这四个灯亮没亮，然后决定是继续走还是跳到别处。

#### 1. 谁在控制红绿灯？(Setting Condition Codes)

除了我们熟知的 `add`, `sub` 会顺便改变标志位，汇编里还有两个**专门**用来设置标志位，但不产生运算结果的指令。**这是考试填空题的常客！**

- **`cmpq b, a` (Compare)**：
	- **动作**：计算 `a - b`（注意顺序！是第二个减第一个）。
	- **区别**：它**不保存结果**！它只根据结果去设置标志位（CF, ZF, SF, OF）。
	- *类比*：就像假装打一拳，看看会不会疼（标志位变没变），但不会真的把人打伤（寄存器值不变）。
	- **用途**：用于 `if (a == b)` 或 `if (a > b)` 这种比较。
- **`testq b, a` (Test)**：
	- **动作**：计算 `a & b` (按位与)。
	- **区别**：同样**不保存结果**，只设置标志位（主要是 ZF 和 SF）。
	- **经典用法**：**`testq %rax, %rax`**。
		- 计算 `%rax & %rax`。
		- 如果 `%rax` 是 0，结果就是 0 $\rightarrow$ **ZF=1**。
		- 如果 `%rax` 是负数，结果最高位是 1 $\rightarrow$ **SF=1**。
		- *用途*：检查 `%rax` 是正数、负数还是零。

------

#### 2. 读取红绿灯：Set 指令 (Reading Condition Codes)

有时候我们不需要跳转，只想知道“刚才的比较结果是真还是假”。这就用到了 `set` 指令。

- **`set` 家族**：`sete` (相等则设为1), `setg` (大于则设为1), `setl` (小于则设为1)...
- **动作**：根据当前的标志位组合，把**目的寄存器的最低 1 个字节**（也就是 `%al` 那一截）设置为 0 或 1。
- **坑点**：它**只改变最低的 1 个字节**，寄存器里剩下的高位字节（比如 `%rax` 的高 7 个字节）**不会被清零**！
	- *考试代码题*：通常会在 `set` 之前先来一句 `movzbl` 或者 `xor` 清零，防止高位垃圾数据干扰。

------

#### 3. 决定去向：跳转指令 (Jump) —— **⭐ 核心中的核心**

这是你看懂汇编逻辑流的关键。`jmp` 分为“直接跳”和“看脸色跳”。

- **无条件跳转**：
	- `jmp Label`：不管三七二十一，直接跳到 Label 去执行。
- **有条件跳转 (Conditional Jump)**：
	- **`je` / `jne`**：相等(Equal)就跳 / 不等(Not Equal)就跳。
		- *看 ZF 灯*。
	- **`js` / `jns`**：是负数(Signed)就跳 / 非负就跳。
		- *看 SF 灯*。
- **有符号数 (Signed) 比较跳转**（最常用，处理 `int`）：
	- **`jg` (Greater)**：大于就跳 $(>)$。
	- **`ge` (Greater or Equal)**：大于等于 $(>=)$。
	- **`jl` (Less)**：小于就跳 $(<)$。
	- **`le` (Less or Equal)**：小于等于 $(<=)$。
	- *原理（不用死记，理解即可）*：比如 `jl` (小于)，它看的是 `SF ^ OF`。如果发生了溢出（OF=1）或者结果是负的（SF=1），综合判断逻辑真假。
- **无符号数 (Unsigned) 比较跳转**（处理指针或 unsigned）：
	- **`ja` (Above)**：高于 $(>)$。
	- **`jb` (Below)**：低于 $(<)$。
	- *记忆法*：无符号数没有正负，只有高低，所以用 A/B (Above/Below)，不用 G/L (Greater/Less)。

---

### 第二阶段：控制流结构的翻译 (Control Flow)

#### 1. 条件传送：`cmov` 指令 (Conditional Move) —— **⚡️ 性能优化黑科技**

在讲 if-else 之前，必须先讲一个特殊指令。

普通的 if-else 需要跳转（Jump），但 CPU 并不喜欢跳转（因为会打断流水线，导致预测失败，效率降低）。

所以，现代 CPU 增加了一种“不跳转”的条件指令：cmov。

- **格式**：`cmovX Src, Dest` （X 是条件，比如 `e`, `g`, `l` 等）。

- 原理：“我全都要！”

	CPU 会先把 if 和 else 两个分支的结果都算出来，分别放在两个地方。然后根据标志位，用 cmov 指令决定把哪个结果搬到最终寄存器里。

- **例子** (参考 Slide 18/25)：

	C

	```
	val = (x > y) ? (x - y) : (y - x);
	```

	汇编逻辑：

	1. 先算 `x - y` 存到 `%rax`。
	2. 再算 `y - x` 存到 `%rdx`。
	3. 比较 `cmpq %rsi, %rdi` (x:y)。
	4. **`cmovle %rdx, %rax`**：如果 `x <= y`，就把 `%rdx` 搬给 `%rax`（覆盖掉原来算的 `x-y`）。

- **优点**：不需要跳转，流水线极其流畅。

- **缺点/坑点**（必考判断题）：

	- **计算昂贵**：如果两个分支里都有很复杂的计算（比如 `foo(x)`），算两个太亏了，编译器就不会用 `cmov`。
	- **副作用**：如果分支里有 `x++` 或者空指针解引用，提前把两个都算一遍会导致错误（比如空指针崩溃）。

------

#### 2. 循环结构：`do-while` —— **🌀 汇编的“亲儿子”**

这是汇编里最自然的循环结构，因为汇编习惯“先干活，再检查要不要继续”。

- **C 语言**：

	C

	```
	do {
	    body-statement;
	} while (test-expr);
	```

- **汇编逻辑**：

	代码段

	```
	loop:
	    Body ...      ; 执行循环体
	    cmp ...       ; 计算测试条件
	    jX loop       ; 如果条件成立，跳回 loop
	```

- **特点**：至少执行一次。这也是逆向分析时识别 `do-while` 的标志。

------

#### 3. 循环结构：`while` —— **🎭 两种翻译套路**

`while` 循环可能不执行（如果一开始条件就是假），所以汇编处理稍微复杂点。根据编译器的优化等级（`-Og` 或 `-O1`），有两种翻译方式：

**套路一：Jump-to-middle (跳到中间法)** —— *GCC -Og 默认*

- **逻辑**：先把程序跳转到循环结尾的测试部分，如果通过测试，再跳回开头执行 Body。

- **结构**：

	Plaintext

	```
	    jmp test      ; 1. 刚开始直接跳到测试处
	loop:
	    Body ...      ; 3. 执行循环体
	test:
	    cmp ...       ; 2. 进行测试
	    jX loop       ; 4. 如果成立，跳回 loop
	```

- **识别技巧**：看到代码还没开始跑就先来个 `jmp` 跳到后面的，通常是 `while`。

**套路二：Guarded-do (保镖法)** —— *GCC -O1 优化*

- 逻辑：把 while 变成 if + do-while。

	先用一个 if 检查条件。如果条件为假，直接跳过整个循环（Loop 不执行）。如果为真，就进入一个标准的 do-while 循环。

- **结构**：

	Plaintext

	```
	    cmp ...
	    jX done       ; 1. 门卫：如果初始条件不成立，直接滚蛋
	loop:
	    Body ...      ; 2. do-while 结构
	    cmp ...
	    jX loop       ; 3. 回头
	done:
	```

- **优点**：少了一次无条件跳转，循环内部效率更高。

------

#### 4. 循环结构：`for` —— **🍬 只是语法糖**

for 循环其实就是 while 循环的变体。

C 语言：for (Init; Test; Update) Body

$\downarrow$

转化为 while：

C

```
Init;
while (Test) {
    Body;
    Update;  // 注意 Update 在 Body 之后执行
}
```

- **汇编考点**：做逆向题时，你要能在汇编里找到这四个部分：
	1. **Init**：循环前的初始化（如 `mov $0, %eax`）。
	2. **Test**：决定是否退出的比较（`cmp`）。
	3. **Body**：核心逻辑。
	4. **Update**：循环变量的变化（如 `add $1, %rbx`）。**注意：Update 通常在跳转指令（Test）的前面。**

### 第三阶段：Switch 与跳转表 (Jump Tables)

#### 1. 为什么要用 Switch？

如果你写一堆 `if-else if-else`，CPU 需要一个接一个地比较（O(n) 时间）。 但 Switch 语句（在 Case 比较紧凑时）可以做到 **O(1)** 的时间！不管你有 100 个 Case 还是 3 个 Case，速度是一样的。

#### 2. 魔法道具：跳转表 (Jump Table) —— **⭐ 必考结构**

编译器会在此处施展魔法：它不生成一堆 `cmp` 指令，而是生成一个**数组**（也就是“表”）。

- **数组的内容**：不是整数，而是**代码地址**（就是 `.L1`, `.L2` 这些标签的地址）。
- **存放位置**：通常放在只读数据段 **`.rodata`** (Read-Only Data)。

**🔍 汇编长什么样？** 这是 Switch 最标志性的指令，看到它就是 Switch：

代码段

```
jmp *.L4(,%rdi,8)
```

- **注意那个 `\*` 号**：代表**间接跳转 (Indirect Jump)**。意思是：“别跳到 `.L4` 这个地址去！而是去 `.L4` 这个地方查表，把查到的值作为新地址跳过去。”
- **`.L4`**：跳转表的基地址（数组开头）。
- **`%rdi`**：索引值（你的 `switch(x)` 里的 `x`）。
- **`8`**：因为在 64 位系统里，一个地址占 8 字节。

**🐱 猫咪比喻**：

- **If-else**：像你在找书，你要一本一本看书脊：“是这本吗？不是。是这本吗？不是。”（慢）
- **Switch (跳转表)**：像大楼的电梯按钮。你要去 5 楼，直接按“5”，电梯通过电路（查表）直接把你送到 5 楼，不需要先去 1 楼、2 楼、3 楼问一遍。

#### 3. 两个关键细节 (Missing Cases & Fall Through)

1. **缺少的 Case 怎么办？**
	- 如果你的 Switch 写了 `case 1`, `case 2`, `case 5`。中间缺了 3 和 4 怎么办？
	- 编译器会在跳转表里把索引 3 和 4 的位置填上 **Default (或 def)** 的地址。这样你查表查到 3 的时候，就自动跳去 Default 了。
2. **Fall Through (穿透)**
	- C 语言里如果不写 `break`，程序会继续执行下一个 Case。
	- 在汇编里体现为：**代码块之间没有 `jmp` 或 `ret`**，直接连在一起。
	- *这也是 Switch 容易出 Bug 的地方，汇编能很清楚地看出来有没有 break。*

### 第一阶段：有借有还 (The Stack & Control Flow)

#### 1. 什么是“栈帧” (Stack Frame)？

你可以把栈（Stack）想象成一个 **“函数租房中心”**。

- 每当一个函数被调用（比如 `main` 调用 `add`），系统就会给 `add` 在栈上分配一块专属的内存空间，这块空间就叫 **栈帧 (Stack Frame)**。
- `add` 函数执行期间，它的局部变量、临时数据都住在这个房间里。
- 当 `add` 函数返回（`ret`）时，这个房间就被“退租”了（栈指针回退），里面的数据就被废弃了。

**栈的指针 (重要复习)**：

- **`%rsp` (Stack Pointer)**：永远指向**栈顶**（最下面，因为栈向下生长）。它是栈帧的“地基”。

------

#### 2. 最关键的指令：`call` 和 `ret` —— **⭐ 必考核心机制**

在 C 语言里，你写 `foo()` 就调用了。但在汇编里，这是一套精密的配合。

**① `call Label` (函数调用)** 这个指令其实**偷偷做了两件事**（一定要背下来）：

1. **压栈返回地址**：它把 `call` 指令**后面紧接着的那条指令的地址**（也就是函数回来后该继续执行的地方）压入栈中。
	- *为什么要压栈？* 就像你打游戏时突然要去上厕所，你得先存个档（保存返回地址），上完厕所才能回来接着玩。
2. **跳转**：把 `%rip`（程序计数器）修改为函数的起始地址（Label）。

**🐱 例子辅助**： 假设代码如下：

代码段

```
0x400544:  call  0x400550 <mult2>  ; 调用 mult2 函数
0x400549:  mov   %rax, %rdx        ; <-- 这是“返回地址”
...
0x400550 <mult2>:                  ; mult2 函数的入口
```

- 执行 `call` 时：
	1. CPU 把 **`0x400549`** (下一条指令地址) 压入栈顶。
	2. CPU 跳去 **`0x400550`** 开始执行 `mult2`。

------

**② `ret` (函数返回)** 这个指令也**偷偷做了两件事**（与 `call` 完美对称）：

1. **弹栈**：从栈顶弹出一个值（这个值就是刚才存的返回地址）。
2. **跳转**：把 `%rip` 设置为这个弹出来的地址。
	- *注意*：`ret` 根本不知道它是从哪来的，它只管**盲目地**去信栈顶的那个数字。**这就是缓冲区溢出攻击的原理——如果你偷偷改了栈顶的这个数字，`ret` 就会带你去任何你想去的地方（比如黑客代码）！**

------

#### 3. 栈帧的生长与消亡 (Stack Frame Lifecycle)

让我们看看一个函数 `P` 调用函数 `Q` 时，栈是怎么变化的（Slide 13-15）：

1. **P 正在运行**：`%rsp` 指向 P 的栈帧底部。
2. **P 调用 Q (`call Q`)**：
	- **返回地址**被压入栈。
	- `%rsp` 往下移了一格。
	- 现在 `%rip` 指向 Q 的代码。
3. **Q 开始运行**：
	- Q 可能会继续把 `%rsp` 往下移（`subq $16, %rsp`），给自己开辟新的空间（分配局部变量）。
	- 这时候，**从返回地址往下，到新的 `%rsp` 之间**，就是 Q 的栈帧。
4. **Q 执行完毕 (`ret`)**：
	- Q 必须先把 `%rsp` 移回去（`addq $16, %rsp`），释放自己的空间。
	- 执行 `ret`，弹出返回地址。
5. **回到 P**：`%rsp` 回到了 P 调用 Q 之前的状态，就像 Q 从来没存在过一样。
